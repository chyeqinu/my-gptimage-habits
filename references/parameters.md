# 参数规则

> 全部基于 272 条真实任务的统计。规则优先级：本文件 > 模型默认。

## 1. 模型与接口（固定）

| 参数 | 固定值 | 说明 |
|---|---|---|
| `model` | `gpt-image-2` | 100% 任务使用 |
| 接口 | `https://speed.ai-pixel.online/v1/images/generations` | 你的活动配置（profile “图片”） |
| 备用接口 | `https://api.ai-pixel.online` | profile “image”，超时可放宽到 1000s |
| `apiMode` | `images` | OpenAI 兼容 images 接口 |
| `timeout` | 600–1000s | 复杂任务（多图/21:9/长 prompt）用 1000s |

## 2. 接口协议（已对照平台源码核实，2026-09-01）

- 无参考图：`POST {base}/v1/images/generations`（JSON 体）
- 有参考图：`POST {base}/v1/images/edits`（multipart，图片放 `image[]` 字段，
  文件名 `input-1.png`、`input-2.png`…，顺序 = @图1/@图2…）
- prompt 里的 `@图N` 在发送前会被转成 `[image N]`（1 起）
- `size=auto` 且无输入图时，由模型自行决定输出尺寸（同一批任务尺寸可能不同）
- **接口不支持 `background: transparent`**（gpt-image-2 实测 HTTP 400）；
  真透明底 = prompt 追加 [背景指令] 块 + 生成后本地键色抠除（见下）
- **接口不支持单请求 n>1**（“n greater than 1 is not supported”）；
  要 2 张 = 连续发 2 次 n=1（技能脚本自动处理）

## 3. `size`（请求尺寸）

**默认 `auto`（85%）——跟随输入图的比例与尺寸。** 只有目标比例和输入图不一致，
或没有输入图、需要指定比例时才显式写。

历史显式尺寸分布与用途：

| size | 次数 | 你的典型用途 |
|---|---|---|
| `720x1280` | 16 | **9:16 竖版**：短视频封面、竖版字幕条 |
| `2160x1440` | 12 | **3:2**：校标/logo 设计、视频挂角（大画布） |
| `1280x720` | 9 | **16:9**：横版视频封面、片头字幕 |
| `1920x816` | 2 | **21:9**：PPT 大屏封面（“比例21:9”） |
| `1024x1024` | 1 | **1:1**：方图转换（“尽可能保留图片信息”） |

比例选择规则：

| 目标 | size |
|---|---|
| 竖屏短视频（9:16） | `720x1280` |
| 横屏视频/横版封面（16:9） | `1280x720` |
| PPT 大屏（21:9） | `1920x816` |
| 校标/logo 素材（3:2） | `2160x1440` |
| 方图（1:1） | `1024x1024` |
| 有参考图且不改比例 | `auto` |

注意：你习惯**在 prompt 里同时写明比例**（如“（16：9）”“9：16”“比例21:9”），
即使 size 已指定。比例在 prompt 里再强调一次是你的固定习惯，保留它。

## 4. `quality`

| 值 | 占比 | 规则 |
|---|---|---|
| `auto` | 90% | **默认。几乎永远用它。** |
| `medium` | 10% | 大批量出字幕条/改字时可省一点（你偶尔用过） |
| `high` | 0.7% | 不用。仅当用户明确要求“文字要特别清晰”才考虑 |

## 5. `n`（一次出几张）

| 值 | 占比 | 规则 |
|---|---|---|
| `1` | 86% | **默认**：模板已定型、改字、抠图、合成 → 1 张 |
| `2` | 12% | **首次设计**封面/字幕条/PPT 封面时出 2 张让用户挑 |
| `3` | 2% | 只在明显“探索期”（同一设计反复试风格）才用 |

判断口诀：**“定稿动作”n=1，“探索动作”n=2。**

注意：接口不支持单请求 n>1，出 2 张实际是**连续 2 次 n=1 请求**（技能脚本自动串行执行。
网页端开启 streamImages 时 n>1 会并发发请求，这正是你历史上 Concurrency limit 失败的根源）。

## 6. `output_format` / `moderation` / `transparent_output`

| 参数 | 规则 |
|---|---|
| `output_format` | **永远 `png`**（100% 任务） |
| `moderation` | `auto`（100%） |
| `transparent_output` | 平台 UI 的“透明底”开关。接口层面**没有**对应参数；实现链路 =
  prompt 追加 [背景指令] 块 → 模型画纯色底（默认 #00FF00，主体含绿色系时用 #FF00FF）→
  平台本地按边界泛洪把键色抠掉，输出真透明 PNG。技能脚本 `--transparent` 完整复刻该链路。 |

**抠图习惯（重要）**：你 90% 的抠图用绿幕方式——prompt 写
**“背景设置为方便抠图的纯绿色背景”**，交付绿底 PNG 给剪辑软件做色度键
（剪辑软件对不纯的绿有容错，不需要像素级纯色）。少数场景（22 次“真透明底”）走真透明链路。

- 默认抠图：绿底（prompt 写“方便抠图的纯绿色背景”）
- 用户明说“透明底/真透明底”：`--transparent`（自动追加 [背景指令] + 本地抠键色，输出带 alpha 的 PNG）

[背景指令] 块原文（平台 `transparentImage.ts`）：

```
[背景指令]
背景色选择规则：如果主体包含绿色系（绿、青绿、黄绿、草绿等）颜色，使用纯洋红色(#FF00FF)背景；否则一律使用纯绿色(#00FF00)背景。
背景要求：整张画布仅由所选纯色填充，无任何渐变、纹理、阴影、光照变化、地面或环境元素。
主体要求：单主体、完整呈现、轮廓清晰锐利。主体与背景之间保持干净的边缘分离，不要有颜色溢出或混合。
禁止：主体本身、描边、光晕、投影或反射中不能出现所选背景色。
```

## 7. 参考图（input images）

- 75% 的任务带参考图。上传顺序 = prompt 里的引用顺序：`@图1`、`@图2`…
- 分布：1 张 169 次（主流）、2 张 22 次（合成/替换素材）、3 张 8 次、5 张 4 次（群像封面）。
- 带参考图时 `size` 几乎必然 `auto`（跟随原图）。
- 合成任务里要**在 prompt 中写清每张图的角色与位置**（“图二人物加到图一右侧”）。

## 8. mask

你几乎不用 mask（272 次里 1 次）。抠图交给模型（“提取出来”），不用遮罩。
规则：默认不用 mask。

## 9. 并发与超时（来自失败样本）

- 3 次失败为 `Concurrency limit exceeded`：**一次只发一个请求**，等完成再发下一个。
  出 2 张由技能脚本串行发 2 次 n=1 完成，不要自己开并发。
- 1 次失败为“请求超时：超过 1000 秒”：复杂任务（多图合成、长结构化 prompt）
  把 timeout 设为 1000s；仍超时就拆需求或重试。
- 其他已实测的接口限制：单请求 n>1 被拒（自动退化为串行）、`background: transparent` 被拒
  （自动改走 [背景指令]+本地抠键色）。
