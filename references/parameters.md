# 参数规则

> 全部基于 272 条真实任务的统计。规则优先级：本文件 > 模型默认。

## 1. 模型与接口（固定）

| 参数 | 固定值 | 说明 |
|---|---|---|
| `model` | `gpt-image-2` | 100% 任务使用 |
| 接口 | `https://ai-pixel.online/v1/images/generations` | **当前端点（2026-09 起）** |
| 历史接口 | `https://speed.ai-pixel.online`（profile “图片”）/ `https://api.ai-pixel.online`（profile “image”） | 已弃用/备用 |
| `apiMode` | `images` | OpenAI 兼容 images 接口 |
| `timeout` | 600–1000s | 复杂任务（多图/21:9/长 prompt）用 1000s |

## 2. 接口协议

- 无参考图：`POST {base}/v1/images/generations`（JSON 体）
- 有参考图：`POST {base}/v1/images/edits`（multipart，图片放 `image[]` 字段，
  文件名 `input-1.png`、`input-2.png`…，顺序 = @图1/@图2…）
- prompt 里的 `@图N` 在发送前会被转成 `[image N]`（1 起）
- **接口不支持 `background: transparent`**（实测 HTTP 400，勿发）
- **单请求 n>1 行为不稳定**（中转站按账号随机分配，用户实测有时可以）：
  要 2 张 = 文生图先试 n>1（被拒自动多试 2 轮），图生图直接连续发 2 次 n=1（技能脚本自动处理）

### 2.1 当前中转站实测行为（2026-09-04 @ ai-pixel.online，重要）

**平台参数 UI 基本不作用到出图上，提示词才是控制项**：

| 实测 | 操作 | 结果 | 结论 |
|---|---|---|---|
| 比例 | prompt 写“（16：9）”，size=auto | 1672x941（16:9） | ✅ 比例听 prompt |
| 比例 | prompt 写“（9：16）”，size=auto | 941x1672（9:16） | ✅ 比例听 prompt |
| 比例 | 无比例 prompt，size=720x1280 | 1672x941（16:9） | ❌ **size 参数被忽略** |
| 透明（文生图） | 无参考图 + prompt 含“透明底” | RGBA PNG（73% 像素 alpha=0，无颜色残留，视觉验证棋盘格透出） | ✅ **文生图：透明听 prompt**，且排版设计质量比绿底版更好 |
| 透明（图生图） | 带参考图 + prompt“透明底”（用户实测 + 脚本实测） | 返回 RGBA 但**提取结果严重劣化**（元素模糊成污渍/整图空白，实测 2/2 不可用） | ❌ **图生图：“透明底”实际不可用** → 改绿底 + `--unkey` |
| n>1（文生图） | 单请求 n=2 | 时而被拒（“not supported for OAuth image accounts”）——中转站账号随机分配 | ⚠️ 脚本先试 3 轮（10s 间隔可能换账号），仍拒则串行 n=1 |
| n>1（图生图） | 单请求 n=2（多次实测） | 全被拒，且**之后的大文件上传会报 `multipart: NextPart: EOF`**（网关被弄坏） | ❌ 图生图**不试 n>1**，直接串行 n=1 |
| 参考图 | edits + 1 张参考图（2.6MB 原图） | 正常 | ✅ edits 链路正常，大文件可传 |

推论（规则依据）：
1. **比例必须写进 prompt**（“（16：9）”“（9：16）”“比例21:9”），`size` 恒用 `auto`。
2. **透明底分两种情况**：
   - **文生图（无参考图）**：prompt 写“透明底”→ 直接返回真透明 PNG，
     **排版设计质量比绿底版更好**——首选。
   - **图生图（有参考图，如从图里提取字幕条/纯标题要透明）**：prompt“透明底”不可用
     （端点虽返回 alpha 通道，但提取结果严重劣化：元素模糊成污渍或整图空白，实测 2/2）→
     改走绿底链路：prompt 写“背景设置为方便抠图的纯绿色背景”+ 技能脚本 `--unkey`
     （出绿底图后本地抠键色，输出真透明 PNG）。
3. **n>1 不稳定**（中转站账号池问题）：文生图先试（脚本最多 3 轮），图生图直接串行 n=1
   （实测 n>1 尝试会弄坏后续大文件上传）。
4. `--transparent`（[背景指令]+本地抠键色）= 文生图“透明底”没生效时的**兜底**；
   图生图透明用 `--unkey`（不改 prompt）。

## 3. `size`（请求尺寸）

**恒用 `auto`（85% 习惯 + 新端点参数被忽略的双重理由）。比例控制只走 prompt：**

| 目标 | prompt 里怎么写 | 实测输出 |
|---|---|---|
| 竖屏短视频（9:16） | “（9：16）” | ~941x1672 |
| 横屏视频/横版封面（16:9） | “（16：9）” | ~1672x941 |
| PPT 大屏（21:9） | “（21：9）”或“比例21:9” | 模型自适应宽幅 |
| 校标/logo 素材（3:2） | “（3：2）” | 模型自适应 |
| 方图（1:1） | “（1：1）” | 模型自适应 |
| 有参考图且不改比例 | 不写比例（跟随原图） | 跟随输入图 |

历史显式尺寸分布（仅存档，不再依赖）：720x1280 ×16、2160x1440 ×12、1280x720 ×9、
1920x816 ×2、1024x1024 ×1。

注意：你习惯**在 prompt 里写明比例**——现在这不只是习惯，而是**唯一生效的控制方式**。

## 4. `quality`

| 值 | 占比 | 规则 |
|---|---|---|
| `auto` | 90% | **默认。几乎永远用它。** |
| `medium` | 10% | 大批量出字幕条/改字时可省一点（你偶尔用过） |
| `high` | 0.7% | 不用。仅当用户明确要求“文字要特别清晰”才考虑 |

## 5. `n`（一次出几张）

| 值 | 占比 | 规则 |
|---|---|---|
| `1` | 86% | **默认**：模板已定型、改字、抠图、合成 → 1 张 |
| `2` | 12% | **首次设计**封面/字幕条/PPT 封面时出 2 张让用户挑 |
| `3` | 2% | 只在明显“探索期”（同一设计反复试风格）才用 |

判断口诀：**“定稿动作”n=1，“探索动作”n=2。**

注意：中转站对单请求 n>1 **行为不稳定**（按账号随机分配，有时支持有时拒绝）：
- **文生图**：技能脚本先按 n>1 发，被拒自动多试 2 轮（10s 间隔，可能换到支持的账号），
  仍拒则退化为连续 n=1。
- **图生图**：技能脚本**直接**连续发 n 次 n=1（实测图生图 n>1 尝试会让网关对后续
  大文件上传报 `multipart EOF`，不划算）。
（网页端开启 streamImages 时 n>1 会并发发请求，这正是你历史上 Concurrency limit 失败的根源。）

## 6. `output_format` / `moderation` / 透明底

| 参数 | 规则 |
|---|---|
| `output_format` | **永远 `png`**（100% 任务） |
| `moderation` | `auto`（100%） |
| 透明底 | **分文生图 / 图生图两种**（见下）。平台“透明底”开关、`background` 参数**都不用** |

**透明底规则（2026-09-04 用户实测 + 脚本验证，重要）：**

- **文生图（无参考图）→ prompt 写“透明底”**：当前端点直接返回带 alpha 的真透明 PNG
  （实测 73% 像素全透明、无颜色残留），且**排版设计质量比绿底版更好**——首选。
- **图生图（有参考图，如从图里提取字幕条/纯标题要透明）→ 绿底链路**：prompt“透明底”不生效，
  改为 prompt 写“背景设置为方便抠图的纯绿色背景”+ 技能脚本 `--unkey`
  （出绿底图后本地抠键色，输出真透明 PNG；已带 alpha 自动跳过）。
- 兜底：文生图“透明底”个别时候没生效（返回无 alpha，脚本会警告）→ 加 `--transparent`
  （自动追加 [背景指令] 块 + 本地键色抠除，与平台 `transparentImage.ts` 同算法）。

**抠图习惯（重要）**：你 90% 的抠图用绿幕方式——prompt 写
**“背景设置为方便抠图的纯绿色背景”**，交付绿底 PNG 给剪辑软件做色度键
（剪辑软件对不纯的绿有容错，不需要像素级纯色）。少数场景（22 次“真透明底”）要真透明。

- 默认抠图：绿底（prompt 写“方便抠图的纯绿色背景”），直接交付
- 文生图要透明：prompt 末尾加“透明底”二字，直接出透明 PNG
- 图生图要透明：prompt 写绿底 + `--unkey`，本地抠键色出透明 PNG

[背景指令] 块原文（平台 `transparentImage.ts`，仅兜底时使用）：

```
[背景指令]
背景色选择规则：如果主体包含绿色系（绿、青绿、黄绿、草绿等）颜色，使用纯洋红色(#FF00FF)背景；否则一律使用纯绿色(#00FF00)背景。
背景要求：整张画布仅由所选纯色填充，无任何渐变、纹理、阴影、光照变化、地面或环境元素。
主体要求：单主体、完整呈现、轮廓清晰锐利。主体与背景之间保持干净的边缘分离，不要有颜色溢出或混合。
禁止：主体本身、描边、光晕、投影或反射中不能出现所选背景色。
```

## 7. 参考图（input images）

- 75% 的任务带参考图。上传顺序 = prompt 里的引用顺序：`@图1`、`@图2`…
- 分布：1 张 169 次（主流）、2 张 22 次（合成/替换素材）、3 张 8 次、5 张 4 次（群像封面）。
- 带参考图时 `size` 恒 `auto`（跟随原图；且当前端点 size 参数本就不生效）。
- 合成任务里要**在 prompt 中写清每张图的角色与位置**（“图二人物加到图一右侧”）。

## 8. mask

你几乎不用 mask（272 次里 1 次）。抠图交给模型（“提取出来”），不用遮罩。
规则：默认不用 mask。

## 9. 并发与超时（来自失败样本）

- 3 次失败为 `Concurrency limit exceeded`：**一次只发一个请求**，等完成再发下一个。
  出 2 张由技能脚本串行发 2 次 n=1 完成，不要自己开并发。
- 1 次失败为“请求超时：超过 1000 秒”：复杂任务（多图合成、长结构化 prompt）
  把 timeout 设为 1000s；仍超时就拆需求或重试。
- 其他已实测的接口行为/限制：
  - **单请求 n>1 行为不稳定**（2026-09-04 实测，中转站账号随机分配）：文生图脚本自动
    多试 2 轮再串行；图生图直接串行 n=1（n>1 尝试会弄坏后续大文件上传）
  - `background: transparent` 被拒（透明底改走 prompt“透明底”）
  - **size 参数被忽略**（2026-09-04 实测）：比例只认 prompt，勿在参数上花心思
  - **prompt“透明底”只在文生图出透明 PNG**（2026-09-04 实测）；图生图“透明底”不生效，
    改绿底 + `--unkey`；文生图若个别时候没生效（返回无 alpha），脚本会警告，加 `--transparent` 兜底
  - **`multipart EOF`（上传被网关拒读）**（2026-09-04 实测，机制已修正）：
    - 触发条件：**同一图片短时间反复上传**（本次为 30 分钟内传同一照片 10+ 次）
    - 表现：该图任何尺寸/编码的上传都被截断（`multipart: NextPart: EOF`），
      其他图片（小图/新内容）正常；**窗口约 1 小时，自行恢复**（恢复后原图直传成功，
      含 curl 与 Python 两种客户端；排除“内容被永久拉黑”假设）
    - 处理：脚本自动等 45s 重试一次；真被限制时**等 10~30 分钟再发**；
      窗口期内急用可对参考图重编码（裁剪/旋转/换压缩）改字节绕开
