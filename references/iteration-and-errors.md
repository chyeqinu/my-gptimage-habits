# 迭代精修与错误处理

## 迭代精修模式（你的典型节奏）

你从不一遍过，而是“出图 → 一句短句提修改 → 再出图”。修改 prompt 的特征：
**短、只说改什么、必带保护句**。

| 修改意图 | 你的典型 prompt |
|---|---|
| 错字 | `全国体育 体 字错了` |
| 整体更紧凑 | `整体再紧凑些` |
| 某处颜色更高级 | `旁边的字颜色再弄高级一点（蓝色调），其他的完全不变` |
| 换文字保留版式 | `字改成 [新文字]，保留板式` |
| 字更大 | `下面的北京大学要再大一点，背景保持为方便抠图的纯绿色` |
| 位置调整 | `15岁考入清华放上面，下面改成[新文字]，…，其他的完全不变` |
| 去掉某元素 | `去除字幕条上的文字，留空，其他不改变，背景设置为方便抠图的纯绿色背景` |
| 拉长/改行 | `把字幕条整体加长，排版布局不变` / `并改成两行排版（…不是加宽）` |
| 人物调整 | `身体不要重叠了，可以适当调整人物站位保证九个人在画面中` |
| 风格更朴素 | `要素朴一些，不要太花哨` |
| 画面不抢主体 | `占比画面五分之一到四分之一（不要抢占画面）` |
| 不挡人 | `放置在画面上方(不要遮挡人物)` |
| 复用风格 | `跟这个字幕条相同风格，帮我在@图1上加入一个人名字幕条 [文字]` |

**精修规则：**
1. 每轮只改一个维度（颜色 / 大小 / 位置 / 文字），别一次塞多个。
2. 永远带保护句：`其他不变` / `保留板式` / `不改变布局排版`。
3. 绿底/透明状态在迭代中要**每轮重申**（`背景依旧为纯绿色底`）。
4. 同一设计最多迭代 3–4 轮；还不到位就换 `n=2` 重新探索方向。

## 常见错误与修法

| 现象 | 修法 |
|---|---|
| 中文错字 | 缩短/换用该处关键短词，用 W5 改字重试；歧义大的词加引号或拆行 |
| 风格漂移（批量后不像了） | 在 prompt 加“跟[上一张]相同风格”或直接上传定稿图作 `@图1` 参考 |
| 文字遮挡人物 | 加 `不要遮挡人物`，并指明位置（`放置在画面上方`） |
| 文字太大抢画面 | 加 `占比画面五分之一到四分之一（不要抢占画面）` |
| 文字太小不醒目 | 加 `字要大要醒目` / `醒目突出` |
| 合成人物比例怪 | 加 `脚要在一个水平面，身高尽量匹配` / `不要显得太挤` |
| 抠图边缘脏 | 加 `整体降噪处理`；绿底要求“纯绿色” |
| 太花哨 | 加 `不要太花哨` / `要素不要过多` / `简单高级就行` |
| 塑料廉价感 | 加 `文字不要有塑料廉价感` |
| 参考图没按要求放 | 用 `@图N` 明确引用，并写清位置与用途（`logo为图二，校园全景为图三`） |

## API / 平台错误（来自真实失败样本 + 2026-09-04 新端点实测）

| 错误 | 原因 | 处理 |
|---|---|---|
| `Concurrency limit exceeded for account` | 账号并发超限（你的样本里 3 次） | **串行**：等上一个完成再发下一个；出 2 张让技能脚本串行完成，不开多任务 |
| `n greater than 1 is not supported` | 中转站按账号随机分配，n>1 时而被拒（用户实测有时可以） | 文生图：脚本自动多试 2 轮再退串行；图生图：脚本直接串行 n=1（不试 n>1） |
| `background transparent is not supported by gpt-image-2` | 接口拒绝 background 参数 | 不传 background 参数；透明底见下行规则 |
| 图生图（带参考图）prompt 写“透明底”结果不可用 | **透明底只在文生图实际可用**（用户实测 + 脚本实测：图生图端点虽返回 alpha 通道，但提取结果严重劣化——元素模糊成污渍或整图空白） | 图生图要透明：prompt 改“背景设置为方便抠图的纯绿色背景”+ 技能 `--unkey`（本地抠键色出透明 PNG） |
| 出图比例不对（size 参数被忽略） | 当前中转站忽略 size 参数（实测） | 比例写进 prompt：“（16：9）”“（9：16）”“比例21:9” |
| prompt 写了“透明底”（文生图）但返回图无 alpha | 中转站偶发未按透明处理 | 脚本会自动警告；先重试，仍不行加 `--transparent`（[背景指令]+本地抠键色兜底） |
| `read multipart body: multipart: NextPart: EOF` | 两类原因（2026-09-04 实测）：① 批量 400 后网关对大文件上传的临时惩罚窗口（约 1~5 分钟）；② **同一参考图短时间反复上传会被按感知指纹标记，之后该图（任何尺寸/编码）的上传都被静默截断**——随机图和小图正常、同图缩小版全挂、加裁剪/旋转/噪声重编码后立即恢复 | 脚本自动等 45s 重试（对①有效）；若②：对参考图做轻度重编码（裁 2%、旋转 0.5°、加噪、换压缩质量）换掉指纹再传；批量复用同一底图时注意控制上传次数 |
| `请求超时：超过 1000 秒仍未完成` | 复杂任务太慢（多图/长 prompt） | 提高 timeout 到 1000s；仍超就拆需求、减少参考图数量或重试 |
| 接口 401 / 鉴权失败 | API key 失效 | 重新 `--set-key`（见 SKILL.md 第 0 步） |
| 响应无 `b64_json` | 接口异常/限流 | 脚本会同时识别 `url` 字段并下载；仍失败则检查网络或换备用 base_url |

## 交付前自检清单

- [ ] 关键文字与用户原文**逐字一致**（无错字）
- [ ] 比例正确（9:16 / 16:9 / 21:9）——比例靠 prompt 控制，核对输出实际宽高比
- [ ] 绿底任务：背景是**纯绿**、无杂色、元素完整
- [ ] 透明任务：PNG 带 alpha 通道（脚本会自动检查并警告）、边缘干净
- [ ] 合成任务：水平面/身高/脸部细节 OK
- [ ] 风格词（高级感/设计感）体现到位，无“塑料廉价感”
